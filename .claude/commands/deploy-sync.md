# Sync Deployments Workflow - V9

Use this workflow after any V9 contract deployment to ensure the frontend is using the correct addresses.

## Quick Start

```bash
# From repo root
./apps/web/scripts/sync-deployments.sh
```

This script:
1. Reads from `packages/contracts-core/deployments/v9-{chain}.json` (source of truth)
2. Merges all networks into `apps/web/src/config/deployments.json`

## Source of Truth

**Foundry deployment outputs are the canonical source:**
- `packages/contracts-core/deployments/v9-baseSepolia.json`
- `packages/contracts-core/deployments/v9-monadTestnet.json`

These files are generated by deployment scripts and should NOT be manually edited.

## Prerequisites

- V9 contracts deployed successfully
- `packages/contracts-core/deployments/v9-{chainName}.json` exists for your target network
- `jq` installed (for JSON processing)

## 1. Run the Sync Script

```bash
./apps/web/scripts/sync-deployments.sh
```

Expected output:
```
📦 Syncing deployments from contracts-core to frontend...
Source: packages/contracts-core/deployments/v9-*.json
Target: apps/web/src/config/deployments.json
  Processing: v9-baseSepolia.json -> baseSepolia
  Processing: v9-monadTestnet.json -> monadTestnet

✅ Synced to: apps/web/src/config/deployments.json
   Version: 9.9.6

Networks:
  - baseSepolia (chainId: 84532)
  - monadTestnet (chainId: 10143)
```

## 2. Verify On-Chain State

After syncing, verify the contracts are actually live:

```bash
cd packages/contracts-core
source ../../.env

# Check Collateralizer
COLLAT=$(jq -r '.contracts.Collateralizer' deployments/v9-baseSepolia.json)
cast call $COLLAT "usdc()" --rpc-url $BASE_SEPOLIA_RPC_URL

# Check TickBookPoolManager
POOL=$(jq -r '.contracts.TickBookPoolManager' deployments/v9-baseSepolia.json)
cast call $POOL "owner()" --rpc-url $BASE_SEPOLIA_RPC_URL
```

**Expected**: All calls return valid data (not `0x` or revert)

## 3. Test Frontend

```bash
cd apps/web
pnpm dev
```

Verify in browser console:
- No "Contract not found" errors
- No "Collateralizer: not registered" errors
- Markets load with correct probabilities

## 4. Commit Changes

```bash
git add apps/web/src/config/deployments.json
git commit -m "chore: sync V9 deployment configs"
```

## Troubleshooting

### "Collateralizer: not registered" error

**Cause**: Market address not registered with Collateralizer contract

**Solution**:
1. Check the market was deployed with the SAME Collateralizer
2. Verify market registration: `cast call $COLLAT "getOutcomeTokens(address)" $MARKET`
3. If not registered, run the market initialization script

### Frontend shows old addresses

**Cause**: Browser cache or outdated config

**Solution**:
1. Hard refresh browser: `Cmd+Shift+R`
2. Clear localStorage: `localStorage.clear()`
3. Re-run sync script
4. Check `version` field updated in deployments.json

### Script says "No v9-*.json files found"

**Cause**: Deployment artifacts missing

**Solution**: Run the Foundry deployment script first:
```bash
cd packages/contracts-core
forge script script/1_DeployCoreV996.s.sol --broadcast --rpc-url $RPC_URL
```

## File Structure

```
  deployments/

    v9-monadTestnet.json     # Source of truth (Foundry output)

apps/web/
  src/config/
    deployments.json         # Frontend contract addresses (generated)
  scripts/

```

## Adding a New Network

1. Deploy contracts: `forge script ... --rpc-url $NEW_RPC`
2. Save output as `deployments/v9-{chainName}.json`
3. Run sync script — it auto-detects new networks from filenames
4. Add chain config in frontend `wagmi.config.ts` if needed

## Success Criteria

Deployment sync is successful when:
- [ ] Sync script runs without errors
- [ ] On-chain verification passes
- [ ] Frontend loads without contract errors
- [ ] Markets show correct probabilities
- [ ] Trades execute successfully
