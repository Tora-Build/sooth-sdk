# Fee Design Research

**Date:** 2025-12-02  
**Status:** Proposal  
**Impact:** Revenue Model & Sustainability

---

## Executive Summary

Currently, the Sooth Protocol has **zero explicit trading fees**. The only revenue for Liquidity Providers (LPs) comes from the implicit spread (slippage) generated by the LMSR pricing curve. While this is great for early adoption, it is unsustainable for long-term protocol viability, LP incentives, and funding the Guardian system.

**Recommendation:** Implement a configurable **Trading Fee (default 2%)** applied to trade volume, split between:

1.  **Liquidity Providers (50%)**: To deepen liquidity.
2.  **Protocol Treasury (30%)**: To fund development.
3.  **Guardian Rewards (20%)**: To incentivize decentralized adjudication.

---

## 1. Current State Analysis

**Codebase Review:**

- `SoothMarket.sol`: The `trade` function calculates cost via `amm.costDelta` and transfers that exact amount. No additional fee is added or deducted.
- `SoothLMSRReal.sol`: Calculates pure mathematical cost. No fee logic.
- `SoothVault.sol`: Tracks reserves but has no mechanism to siphon off protocol fees.

**Implication:**

- **LPs** only earn when traders lose money (net negative PnL for traders) or from the path-dependence of the LMSR curve (which acts like a small spread).
- **Protocol** earns nothing.
- **Guardians** have no revenue source defined yet.

## 3. Proposed Fee Model

We propose a **Volume-Based Trading Fee** applied at the execution level in `SoothMarket.sol`.

### A. Fee Structure

- **Fee Basis:** Percentage of the _absolute value_ of the trade cost (volume).
- **Default Rate:** **2.0%** (200 bps).
- **Application:**
  - **Buys:** User pays `Cost + Fee`.
  - **Sells:** User receives `Proceeds - Fee`.

### B. Fee Distribution (The "Fee Split")

We propose a 3-way split to align incentives:

1.  **Liquidity Providers (50% -> 1.0%)**:

    - **Why:** Attracts capital to the `SoothVault`.
    - **Mechanism:** Added directly to `marketReserves` in the Vault. This increases the value of `svToken` shares.

2.  **Protocol Treasury (30% -> 0.6%)**:

    - **Why:** Sustainable funding for core dev team, audits, and marketing.
    - **Mechanism:** Sent to a `Treasury` address (multisig).

3.  **Guardian Rewards (20% -> 0.4%)**:
    - **Why:** Critical for the "Decentralized Adjudication" roadmap. Pays guardians for staking and correct marking.
    - **Mechanism:** Sent to `SoothGuardianRegistry` (future contract) or a rewards pool.

## 4. Technical Implementation

### Changes to `SoothMarket.sol`

We need to introduce fee parameters and modify the `trade` function.

```solidity
// State Variables
uint256 public feeBps = 200; // 2%
uint256 public constant MAX_BPS = 10000;

// Fee Split Config (could be in a separate FeeManager contract)
uint256 public lpSplitBps = 5000;       // 50%
uint256 public protocolSplitBps = 3000; // 30%
uint256 public guardianSplitBps = 2000; // 20%

function trade(uint8 outcomeIndex, int256 deltaShares, int256 maxCost) external onlyLive {
    // ... existing checks ...

    // 1. Calculate Pure LMSR Cost
    (int256 cost, ISoothAMM.State memory newState) = amm.costDelta(ammState, outcomeIndex, deltaShares, b);

    // 2. Calculate Fee
    // Fee is always positive, based on absolute cost magnitude
    uint256 absCost = cost >= 0 ? uint256(cost) : uint256(-cost);
    uint256 totalFee = (absCost * feeBps) / MAX_BPS;

    // 3. Apply Fee to User Cost
    int256 finalCost;
    if (cost > 0) {
        // Buy: User pays Cost + Fee
        finalCost = cost + int256(totalFee);
    } else {
        // Sell: User receives Proceeds - Fee (Proceeds are positive magnitude of negative cost)
        // Cost is negative (vault pays user), so we add fee (making it less negative / closer to 0)
        finalCost = cost + int256(totalFee);
    }

    // 4. Slippage Check (on final cost)
    require(finalCost <= maxCost, "Market: slippage exceeded");

    // 5. Distribute Fees
    // Calculate splits
    uint256 protocolFee = (totalFee * protocolSplitBps) / MAX_BPS;
    uint256 guardianFee = (totalFee * guardianSplitBps) / MAX_BPS;
    uint256 lpFee = totalFee - protocolFee - guardianFee;

    // Transfer Protocol & Guardian Fees (if > 0)
    // Note: This requires the user to approve the Market to spend their tokens,
    // OR the Vault handles the transfer.
    // Simpler approach: Send everything to Vault, then Vault distributes?
    // Better approach: Market pulls `finalCost` from user.
    //   - If Buy: Market sends `protocolFee` to Treasury, `guardianFee` to Registry, `cost + lpFee` to Vault.
    //   - If Sell: Vault pays `cost` (negative). Market intercepts?
    //   Wait, Sell logic is tricky if Vault pays directly.

    // REVISED FLOW:
    // All funds go through Vault via `recordMarketFlow`.
    // We pass the `fee` breakdown to the Vault.

    vault.recordTradeWithFees(
        marketId,
        cost,           // Pure LMSR cost (goes to marketReserves)
        lpFee,          // Goes to marketReserves (bonus)
        protocolFee,    // Transferred to Treasury
        guardianFee,    // Transferred to Guardian Pool
        msg.sender
    );

    // ... update state ...
}
```

### Changes to `SoothVault.sol`

We need a new function `recordTradeWithFees` to handle the splits atomically.

```solidity
function recordTradeWithFees(
    uint256 marketId,
    int256 lmsrCost,
    uint256 lpFee,
    uint256 protocolFee,
    uint256 guardianFee,
    address trader
) external onlyAuthorized {
    // 1. Net amount trader pays/receives
    int256 netFlow = lmsrCost;

    // Add fees (trader pays them)
    // If lmsrCost > 0 (Buy), trader pays Cost + Fees
    // If lmsrCost < 0 (Sell), trader receives Cost - Fees (Cost is negative, so we add positive fee)
    // In both cases, we ADD the positive fee amount to the flow from the trader's perspective
    int256 totalFee = int256(lpFee + protocolFee + guardianFee);
    int256 traderPays = lmsrCost + totalFee;

    // 2. Execute Transfer
    if (traderPays > 0) {
        asset.transferFrom(trader, address(this), uint256(traderPays));
    } else {
        asset.transfer(trader, uint256(-traderPays));
    }

    // 3. Distribute
    // LP Fee stays in Vault (added to marketReserves implicitly or explicitly)
    // We treat LP fee as "profit" for the market
    marketReserves[marketId] += (lmsrCost + int256(lpFee));

    // Protocol Fee -> Treasury
    if (protocolFee > 0) asset.transfer(treasury, protocolFee);

    // Guardian Fee -> Guardian Registry
    if (guardianFee > 0) asset.transfer(guardianRegistry, guardianFee);
}
```

## 5. Economic Implications

**Scenario:**

- Trader buys 100 YES shares.
- LMSR Cost: 50 USDC.
- Fee (2%): 1 USDC.
- **Total Pay:** 51 USDC.

**Distribution:**

- **LP:** +0.50 USDC (added to reserves).
- **Treasury:** +0.30 USDC.
- **Guardians:** +0.20 USDC.

**Impact:**

- **LPs:** Earn yield on volume, not just trader losses. This makes LPing profitable even in efficient markets.
- **Traders:** Slightly worse execution price (51 vs 50). 2% is high for high-frequency trading but acceptable for retail prediction markets.
- **Protocol:** Sustainable revenue stream.

---

## 6. Recommendations

1.  **Implement `recordTradeWithFees` in `SoothVault`**: This centralizes the money movement and ensures atomic fee distribution.
2.  **Update `SoothMarket`**: Add `feeBps` and fee calculation logic.
3.  **Make Fees Configurable**: Allow the `RiskManager` or `Owner` to adjust fees per market (e.g., lower fees for high-volume stable markets, higher for exotic ones).
4.  **Launch with 0% or Low Fees**: Start with 0% or 0.5% during beta to encourage volume, then raise to 1-2% for mainnet.
