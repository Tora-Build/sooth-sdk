## Overview

The V8.1 frontend is a role-based prediction market interface built with React, TypeScript, Viem, and Wagmi. It follows a **page-based separation** model where different user roles (Traders, Creators, Guardians) have dedicated interfaces optimized for their workflows.

### Key Features

- **Role-Based Pages**: Separate pages for Create, Trade, Pro, Gov, and Learn
- **Educational Content**: Integrated tooltips, guided tours, and sandbox mode
- **Direct Contract Hooks**: Custom hooks using `publicClient.readContract` for reliable data fetching
- **Pure WAD Architecture**: All contract values handled in 18-decimal precision
- **Responsive Design**: Mobile-first with progressive enhancement

## Pages

### 1. Trade Page (`/trade`)

**Target User**: AMM Traders (retail, hedgers)  
**Purpose**: Simple, approachable trading interface

**Features**:
- Market selector with search and category filters
- Large probability display (YES/NO cards)
- Quick trade buttons (10, 50, 100, 500 shares)
- Real-time quote with price impact
- Position display with sell buttons
- Educational tooltips

**Components Used**:
- `SimpleTradingPanel` - Main trading interface
- `MarketItem` - Market selector cards
- `InfoTooltip` - Educational hover content

### 2. Pro Page (`/pro`)

**Target User**: TickBook Traders (HFT, arbitrageurs)  
**Purpose**: Advanced orderbook trading

**Features**:
- Orderbook depth visualization
- Limit order form
- Collateralizer panel (split/merge tokens)
- Keyboard shortcuts
- Compact, data-dense layout

**Components Used**:
- `Orderbook` - Order depth display
- `LimitOrderForm` - Place limit orders
- `CollateralizerPanel` - Token operations

**Note**: Only available for graduated markets

### 3. Create Page (`/create`)

**Target User**: Creators + Adjudicators  
**Purpose**: Market management tools

**Features**:
- Market initialization panel (liquidity deposit)
- Creator dashboard (LP position, fees earned)
- Graduation progress indicator
- Settlement panel (for adjudicators)
- Role badge display

**Components Used**:
- `MarketInitializationPanel` - Deposit USDC, select tier
- `CreatorDashboard` - LP position, fee tracking
- `SettlementPanel` - Resolve market outcome
- `OperatorRoleBadge` - Show user's role

### 4. Gov Page (`/gov`)

**Target User**: Guardians  
**Purpose**: Governance and dispute resolution

**Features**:
- Veto settlement button
- Finalize market button
- Dispute period countdown
- Settlement history

**Components Used**:
- `GuardianPanel` - Veto/finalize controls

### 5. Learn Page (`/learn`)

**Target User**: New users  
**Purpose**: Education and onboarding

**Features**:
- 5-step interactive tutorial
- LMSR curve visualization (draggable)
- Sandbox trading (no real money)
- Trade flow animation
- Progress indicators

**Components Used**:
- `LMSRCurve` - Interactive price curve
- `SandboxTradingPanel` - Practice trading
- `TradeFlowAnimation` - Step-by-step visualization

## Hooks

### V8 Direct Hooks (`src/hooks/v8/direct/`)

These hooks use `publicClient.readContract` directly for more reliable data fetching than Wagmi's multicall.

```typescript
// TruthMarket state
const { market, isLoading, error } = useTruthMarketDirect(marketAddress);
// Returns: { question, creator, adjudicator, guardian, deadline, isLive, isSettled, tStar }

// LaunchpadEngine state
const { launchpad, isLoading } = useLaunchpadMarketDirect(marketAddress);
// Returns: { currentBBase, isGraduated, graduationProgress, creatorDeposit, feesAccrued }

// AMMEngine state
const { amm, isLoading } = useAmmMarketDirect(marketAddress);
// Returns: { qYes, qNo, yesProbability, noProbability }

// Quote calculation
const quote = useAMMQuoteDirect(marketAddress, shares, outcome, isBuy);
// Returns: { cost, fee, deltaShares, newYesPrice, newNoPrice, priceImpact, feeRate }

// Collateralizer tokens
const { collateralizer } = useCollateralizerDirect(marketAddress);
// Returns: { yesToken, noToken }

// Available balance
const { available } = useAvailableBalance(ammEngineAddress);
// Returns: spendable proceeds in WAD
```

### Other Hooks

| Hook | Description |
|------|-------------|
| `useDeployments` | Contract addresses from deployments.json |
| `useMarkets` | Market list from markets.json |
| `useSandbox` | Sandbox mode state management |

## Contract Integration

### ABIs

ABIs are defined in `src/config/abis.ts`:

```typescript
export const V8_ABIS = {
  TruthMarket,
  AMMEngine,
  LaunchpadEngine,
  Collateralizer,
  OutcomeToken,
};

export const ERC20_ABI = [...]; // Standard ERC20
```

### Contract Addresses

Loaded from `deployments.json` via `useDeployments()`:

```typescript
const { contracts, chainId } = useDeployments();
// contracts.TruthMarket, contracts.AMMEngine, etc.
```

### WAD Handling

All contract values are in 18-decimal precision (WAD):

```typescript
// Convert to WAD for contract calls
const sharesWAD = parseUnits(amount, 18);

// Convert from WAD for display
const displayValue = formatUnits(wadValue, 18);
```

### USDC Decimals

MockUSDC on testnet has 6 decimals. Conversion is handled in hooks:

```typescript
// Convert cost from WAD (18) to token decimals (6)
const factor = BigInt(10 ** (18 - decimals));
const costInTokenDecimals = (wadCost + factor - 1n) / factor; // Ceiling division
```

## Design Principles

### 1. Role-Based Separation
Each page is optimized for a specific user type with appropriate information density and actions.

### 2. Progressive Disclosure
Show essential information first, reveal details on demand via tooltips and expandable sections.

### 3. Immediate Feedback
Every action has visual feedback (loading states, success/error toasts, animations).

### 4. Error Resilience
Graceful degradation when data fails to load, clear error messages with recovery actions.

### 5. Educational Integration
Tooltips and "Learn more" links throughout the interface to guide new users.

### 6. Accessibility
Keyboard navigation, focus indicators, screen reader support, color contrast compliance.
